# Publication checklist

The sanitized distribution is `tech-progress/mealie-recipe-archive`, using `release-v1` and immutable SemVer tags. These release instructions do not themselves prove publication: a release requires the live gates below. Internal project/test identifiers and private evidence must never enter the distribution.

1. Qualify build/start/smoke from empty state; inspect FINDINGS.md and close outstanding interactive, concurrency, recovery and security gates. Review license obligations and complete image/SBOM/source privacy audits.
2. Select a real authorized public source repository and existing slash-free release channel. Sanitize its tree: exclude `.local/`, `.env*` except `.env.example`, node_modules, FINDINGS.md and private evidence. Retain README, operational docs, wrapper source, LICENSE.upstream, manifest/lock and every main-upstream link. Use root `/` for a standalone copy or `/mealie-recipe-archive` for a monorepo. No imaginary distribution source is embedded.
A sanitized standalone copy verifies with `PUBLIC_DISTRIBUTION=1 bash scripts/verify.sh`; this skips only the intentionally private FINDINGS.md record, not runtime or source-contract checks.

3. Set TEMPLATE_SOURCE_REPO, TEMPLATE_SOURCE_BRANCH and TEMPLATE_SOURCE_ROOT_DIR. Run `bun install --frozen-lockfile`, `bash scripts/verify.sh`, `bash scripts/smoke.sh`, then evaluate `.railway/railway.ts`. Review public app target 9000, native auth, generated secrets and volume references. GitHub App authorization must be checked separately.
4. Under explicit deployment authorization, create a real draft with the exact service/volume set. Export its serialized configuration to JSON. `bash scripts/restore-template-draft.sh EXPORTED_DRAFT_JSON OUTPUT_JSON` prepares canonical **offline** JSON retaining actual existing IDs; it never calls Railway. Review it before a separately authorized update. `bash scripts/audit-template.sh OUTPUT_JSON` compares source/root/build/start/health/variables/volumes/networking, not runtime availability. Missing services or volumes fail instead of creating fake IDs. Query the actual stored graph and deploy it through `templateDeployV2` into a fresh environment; an image-seeded generator or historical source deployment is not evidence of the final graph.
5. Add the actual returned publication ID/code with `marketplace-metadata.json` fields to root `railway-template-metadata.json`. The description is 45–75 characters; icon identifies the product; origins list every main product. Run root `scripts/sync-template-marketplace.sh` and require root `scripts/audit-template-marketplace.sh` to pass. These root/cloud gates are **not run here**, and per-directory metadata is not a substitute for them.
6. Validate the final release revision, current running replicas and zero crashes, native recipe/media/group workflow, restart and native ZIP restore on a newly empty volume. Online native restoration requires an actual application restart before original-owner login, retained-image bytes and cross-group authorization can qualify it. Health or import success alone is insufficient. Soak the workload and record actual CPU cores/memory units alongside their limits. Stop/cancel every owned source and verification deployment, prove zero active deployments/current running instances, remove owned test resources and delete the disposable project **before publication**. Distinguish pending platform-retention volume rows from actual removal; do not claim billable-storage zero while retention remains. Recheck after any release-channel update. Version/tag/release-channel updates follow TEMPLATE_VERSIONING.md; never move an immutable published version tag.

All test scripts are local; draft tools are offline JSON transformations. They do not implicitly deploy, publish, restore production data, charge an account, or modify GitHub.
